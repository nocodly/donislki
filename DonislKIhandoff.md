# DonislKI — контекст проєкту (для нової сесії)

## Що це
AI-меню-асистент для реального ресторану **Donisl** у Мюнхені (Traditionswirtshaus, партнер броварні Hacker-Pschorr). Гість відкриває сайт (QR-код на столику), бачить **звичайне меню з категоріями** (фото, ціна, опис, алергени), і опційно може натиснути "Ask AI" — відкриється чат-бот, який радить страви/напої з реального меню.

Головний принцип продукту: **80% звичайна навігація по меню, 20% AI**. AI — не головний інтерфейс, а помічник поверх меню.

## Стек

- **Next.js 14 (App Router) + TypeScript + Tailwind CSS + React 18 + lucide-react** — mobile-first, без бази даних, усі дані статичні (TS-файли + JSON).
- **AI**: OpenAI API, модель `gpt-5-mini` (**не Anthropic** — мігровано з Claude на OpenAI в паралельній сесії; `ANTHROPIC_API_KEY` досі лежить у `.env`, але не використовується).
- **Немає БД, немає авторизації, немає замовлень** — свідоме рішення, тримати просто.

## Як усе працює

1. **Меню** рендериться миттєво на клієнті з `lib/menuData.ts` — жодного звернення до AI для перегляду категорій/страв. Мова інтерфейсу автоматично визначається з мови телефону (`navigator.language`), 41 мова (англійська + 40 згенерованих), є RTL для ar/he/fa/ur.
2. **AI-чат** — двоє входів:
   - Плаваюча кнопка "Ask AI" — загальний чат, контекст завжди `{category: null, dish: null}` (не успадковує активну категорію — свідомо виправлений баг).
   - Кнопка "Ask AI about this" на картці страви / в модалці деталей — відкриває чат із контекстом конкретної страви, і **одразу автоматично відправляє** питання "Tell me about X" замість порожнього чату.
3. **Модалка деталей страви** — клік по картці (не по AI-кнопці) відкриває фото, повний опис, ціну (з розмірами, якщо є), пейринг, теги, алергени.
4. **Алергени** — не з офіційних даних ресторану (їх нема), а **проаналізовані мною за складом** страви (глютен у паніровці/кнедлях, молочне у вершкових соусах, сульфіти у вині і т.д.) для всіх 143 позицій. Завжди показується застереження "уточніть у персоналу" — навіть коли алергени вказані.
5. **Фото** — 76 з 143 позицій мають реальні фото (решта 67, здебільшого вино — ще ні). Фото беруться з папки, яку користувач кладе на робочий стіл (`Desktop\Фото Донисл`), і зіставляються з позиціями меню **вручну, візуальним оглядом** (немає автоматичного розпізнавання/OCR — я дивлюсь на кожне фото і вирішую, якій страві воно відповідає, або кажу "не впевнений"). Портретні фото (пляшки, келихи) мають `imageFit: 'contain'`, щоб не обрізались — за замовчуванням `cover` (добре для горизонтальних фото страв на тарілці).
6. **Тижневе меню (Wochenkarte)** — окрема категорія `weekly`, ротаційне меню (сезон лисичок + обідні спецпропозиції пн-пт), портоване окремо від основного Sommerkarte.
7. **Пейринги** — симетричні: у кожної страви є `pairing` (напій), у кожного напою — `pairing` (страва). AI завжди згадує пейринг при рекомендації.

## Типовий робочий процес (для будь-якої зміни)

```bash
npm run typecheck   # tsc --noEmit
npm run lint        # next lint
npm run build       # production build
```
Локальна перевірка — через Browser-прев'ю тул (`.claude/launch.json`, конфіг "donislki", `npm run dev`), **ніколи не Bash для dev-сервера**.

Після перевірки:
```bash
git add ... && git commit -m "..." && git push origin main
```
Потім через RAILWAY_TOKEN перевірити `railway status --json` — `latestDeployment.status` має стати `SUCCESS` з потрібним commitHash (білд займає ~1-2 хв).

## Важливі граблі / нюанси

- **Були паралельні сесії роботи над цим репо** (моя гілка Next.js-переписування розійшлася з іншою сесією, яка зробила OpenAI-міграцію + 41 мову + Wochenkarte). Перед пушем **завжди** `git fetch && git log HEAD..origin/main` — якщо там щось нове, розібратись, а не форсити поверх.
- `.env` має містити і `ANTHROPIC_API_KEY` (легасі, не використовується), і `OPENAI_API_KEY` (актуальний, реально викликається). Якщо локально нема — брати з Railway (`railway variable list --service donislki --json`).
- Перегенерація перекладів на всі 40 мов займає **10-20+ хвилин**, робити у фоні (`run_in_background`). Один окремий виклик мови інколи "висить" 5-6 хв замість 30-60с — це нормально, не обов'язково помилка, зазвичай сама завершується.
- Не використовувати `thinking`/reasoning без потреби в генераторі перекладів — раніше воно зжирало весь token-бюджет на invisible reasoning замість видимого тексту (для OpenAI-версії вже стоїть `reasoning_effort: 'low'`).
- AVIF-фото не читаються напряму інструментом перегляду — конвертувати через `sharp` (`npm install sharp` якщо нема в node_modules, він уже в package.json).
- Не вигадувати страви/ціни/склад/алергени/фото — все ґрунтується на реальних даних ресторану (`data/menu.json` — джерело правди) або консервативному аналізі складу.
